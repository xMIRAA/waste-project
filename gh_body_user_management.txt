File: admin/manage_users.php
Severity: Major

Description:
The admin user management page lacks any update or delete endpoints for user accounts. There is no code to edit an existing user's details or to remove a user from the `users` table. This prevents administrators from updating or removing compromised or outdated accounts and creates an operational gap that may encourage ad-hoc, unsafe fixes to be added later (which could introduce SQL-injection or incorrect password-handling risks).

Reproduction/Impact:
- Admins cannot change a user's role, contact, address, or password via the admin UI.
- Admins cannot remove compromised accounts; developers may be tempted to add a quick raw `DELETE` endpoint without prepared statements.

Suggested fix:
- Add secure update and delete handlers using prepared statements, check row existence and affected_rows, and ensure password re-hashing only when a new password is provided.
